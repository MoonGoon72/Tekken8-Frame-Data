# 기술 영상 확대 상세 화면 목표

## 목표와 종료 조건

기술 목록의 선택 셀이 화면을 채우는 상세 카드로 확대되고, 기술 정보와 영상을 함께 보여주며, 닫으면 원래 위치의 셀로 축소되는 흐름을 구현한다.

설계는 사용자와 최종 확인했다. 구현·검증을 마쳤으며 100% 종료 조건을 충족했다.

- 목표 달성률: **100%**
- 현재 달성률: **100% (100/100점)**
- 아래 다섯 항목은 각각 20점이다. 항목의 모든 조건을 구현하고 검증한 경우에만 점수를 부여한다.
- 작성 중이거나 검증하지 못한 항목은 완료로 계산하지 않는다. 실패하거나 확인하지 못한 필수 검증이 있으면 100%로 처리하지 않는다.
- 각 항목 완료 시 이 문서의 체크 상태, 검증 근거, 달성률을 갱신하고 사용자에게 진행률을 알린다.
- 100%가 되면 활성 목표를 완료 처리하고 변경 내용과 검증 결과를 보고한 뒤 작업을 종료한다. 추가 기능, 커밋, 푸시, PR 생성은 이 목표에 포함하지 않는다.

- [x] **2. 확대·축소 전환과 뒤로가기 — 20점**
  - 선택한 셀에서 화면을 채우는 상세 카드로 확대한다. 목록 안 셀 높이만 늘리는 형태가 아니다.
  - X와 왼쪽 화면 가장자리의 뒤로가기 스와이프로 원래 셀에 축소되어 돌아간다.
  - 드래그 취소 시 상세 화면에 머물며 재생 상태를 불필요하게 초기화하지 않는다.
  - 빠른 연속 탭·닫기 중 재입력에 중복 화면이나 잔여 뷰가 발생하지 않는다.
- [x] **3. 영상 재생과 전체 화면 복귀 — 20점**
  - 기술 탭 이후 즉시 무음 반복 재생한다.
  - 재생/일시정지·진행 바·영상 전체 화면 버튼을 제공한다.
  - 영상 전체 화면을 닫으면 확대 상세 카드로 돌아오고 재생 위치와 반복 재생을 유지한다.
- [x] **4. 재생 생명주기와 기존 예외 동작 — 20점**
  - 상세 닫기 시 재생과 진행 중 URL 요청을 정리한다. 다시 열면 처음부터 재생한다.
  - 앱 전환·화면 잠금 시 일시정지하며 복귀 후 자동 재개하지 않는다. 재생 버튼으로 이어 볼 수 있다.
  - 영상 미연결 셀과 광고 셀은 상세를 열지 않는다.
  - 로딩 표시, 오류 메시지, 재시도를 유지하고 재시도·닫기 이후 늦은 응답이 폐기된 화면을 갱신하지 않는다.
  - 영상 복귀가 기술 metadata나 목록/광고 상태를 불필요하게 초기화하지 않는다.
- [x] **5. 검증과 문서 정리 — 20점**
  - 변경 로직에 직접 관련된 의미 있는 회귀 테스트, `TK8Tests` 전체, 앱 Simulator 빌드를 통과한다.
  - Simulator에서 셀 확대/축소·스와이프 완료/취소·반복 재생·전체 화면 복귀·앱 비활성화 후 수동 재개를 확인한다.
  - 작은 기기, 다크 모드, 큰 Dynamic Type, 긴 기술명·커맨드·설명, 한/영 문구의 가림과 잘림을 확인한다.
  - Reduce Motion에서 전환이 기능을 방해하지 않는지 확인한다. VoiceOver 수동 검증은 사용자 요청에 따라 완료 기준에서 제외한다.
  - iOS 17.0 최소 지원과 기존 UIKit/SwiftUI·Repository/캐시 경계를 유지한다.
  - UI 문구 변경 시 `Localizable.xcstrings`를 확인한다. navigation/책임/DI 흐름 변경은 `docs/architecture.md`에 반영한다.
  - `git diff --check`를 통과하고, 작업 내용·검증 결과를 `implementation-notes.md`에 기록한다.

## 완료 후 UX 정정 — 2026-10-03

사용자는 셀의 내용이 세로로 늘어나는 표현을 원하지 않으며, 실제로 늘리지 않아도 셀에서 전체 화면 상세로 이어지는 느낌이면 충분하다고 정정했다. 필요하면 SwiftUI로 변경해도 되지만 프레임워크 변경 자체가 요구사항은 아니다.

UIKit 전환에서 서로 다른 가로·세로 scale과 셀 snapshot 크기 보간을 제거했다. 상세 내용은 전체 화면의 원래 크기로 유지하고, 둥근 카드의 보이는 영역만 셀 위치에서 화면까지 확장하며 원래 셀 이미지를 제자리에서 교차 페이드한다. 닫기도 같은 원리로 처리하고 Reduce Motion은 기존 fade를 유지한다. 일반 전환 시간은 0.30초다.

관련 테스트 5건과 Simulator build가 통과했다(`/private/tmp/tk8-card-reveal-tests2.xcresult`, `/private/tmp/tk8-card-reveal-build.log`). 실제 UIWindowScene에 연결한 테스트에서 중간 프레임의 상세 bounds/transform이 고정이고 마스크만 이동하는 것을 확인했다. 실제 앱의 열기·X 닫기·스와이프 취소/완료도 확인했다. 녹화: `/private/tmp/tk8-card-reveal-demo.mp4`, 짧은 미리보기: `/private/tmp/tk8-card-reveal-opening.mp4`. 모듈·UI 프레임워크 경계는 변경하지 않았다.
