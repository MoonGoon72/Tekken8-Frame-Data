# 광고 제거 일회성 안내 (#101)

2026-10-27 사용자 승인 설계를 기록한다.

## 목적과 동작

캐릭터 선택 첫 화면에서 광고 제거 기능의 존재를 알린다. 배너 위 앱 영역에 “광고 없이 이용할 수 있어요.”, “알아보기”, 닫기(X)를 표시한다. 팝업이나 자동 구매 요청은 만들지 않는다.

미처리 사용자이며 StoreKit 권한이 `notPurchased`이고 배너가 실제 표시될 때만 안내를 표시한다. 첫 실행부터 대상이며 기존 온보딩/동의 절차를 따른다. 확인 중·확인 실패·구매자는 숨긴다. 광고 로딩 실패, 키보드, 화면 이탈, 원격 중단 시 배너와 함께 공간을 접는다.

노출 자체는 처리하지 않는다. X 또는 알아보기 선택 시 UserDefaults에 처리 여부를 저장한다. 재실행·업데이트 후 유지하며 재설치 후에는 다시 보일 수 있다. 알아보기는 기존 구매 설명 화면으로 push한다. 구매 완료 시 배너와 안내가 사라진다.

## 접근 방식

- 선택: 실제 배너가 표시될 때 위쪽에 안내를 결합한다. 광고 맥락을 보존하고 빈 광고 공간을 만들지 않는다.
- 대안: 광고가 없어도 독립 안내를 표시한다. 발견 가능성은 높지만 이번에 승인한 광고와 함께 표시하는 조건에는 맞지 않는다.
- 기술 목록 안내는 이번 범위에서 제외한다.

## 책임과 제약

UIKit View는 표시·액션, 전용 ViewModel은 권한/처리 상태, Repository는 UserDefaults 저장을 담당한다. BannerAdHost는 선택적 부속 뷰의 배치만 담당한다. DIContainer에서 조립하고 기존 PurchaseNoticeViewController를 공통 생성한다.

iOS 17.0+, 기존 UIKit/SwiftUI 경계 유지. 작은 기기·다크 모드·Dynamic Type·VoiceOver와 한국어/영어를 지원한다. 앱 버전·결제 권한 저장 방식·광고 측정 계약은 변경하지 않는다.

## 검증

안내 최초 자격/상태 전환, 닫기 및 알아보기 후 재생성, 배너 로딩 전/실패/재시도/제거/안내 접기, 구매 화면 경로와 큰 글씨 배치를 검증한다. DI 변경으로 전체 TK8Tests 및 Simulator 앱 빌드를 수행한다.
